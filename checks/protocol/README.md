# Проверки протокола ПЛИС

Объяснение архитектуры и путей данных находится в [руководстве разработчика](../../docks/README.md). В общий запуск CTest также включена структурная проверка `checks/verify_project_structure.py`: исходники в CMake, пояснения к типам и ресурсы QRC.

Этот каталог содержит автоматические проверки по запросу о сравнении Python и редактора, скрипт сравнения `verify_fpga_packets.py` и неизмененный эталон `All_together.py`. Все XML для проверок генерируются скриптом: локальные примеры из `tests/` не требуются. Генерируемые XML/BIN и журналы запуска редактора находятся в `build/verification/`, снимки интерфейса — рядом с тестовым исполняемым файлом в каталоге сборки.

## Запуск

Нужны Qt 6.5+ с Qt Test и Python 3.10+. Эталон находится рядом со скриптом сравнения; команды ниже выполняются из корня репозитория.

```bash
cmake -S . -B build -DAVIONIX_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure
```

На Windows с Visual Studio для выпуска используйте `--config Release` и `ctest -C Release`. В GitHub Actions проверки временно отключены: установщик собирается с `AVIONIX_BUILD_TESTS=OFF`, без запуска CTest. Локально проверки доступны через команды выше.

Отдельное сравнение:

```bash
python3 -B checks/protocol/verify_fpga_packets.py --app build/AvionixDesigner.app/Contents/MacOS/AvionixDesigner
```

## Что проверяется

- Из `All_together.py` загружаются именно его функции упаковки, `VbXML`, `VbDataWorks` и `VbDataLoader`. Главный цикл, подключение порта и OpenCV не исполняются. Запись перехватывается объектом `Capture`.
- Для свежей сцены создаются четыре XML с 3D-видом справа, непрозрачным и прозрачным прямоугольниками, поворачиваемой маской 10×11 и двумя состояниями статической маски. Сцены охватывают все сочетания знаков sin/cos. Данные пересекают границу чанка 1024 байта и неполные тайлы 8×8.
- Каждый из этих же XML загружается настоящим приложением через `--export-bin`. Полный BIN сравнивается с Python, включая 1-байтовую сторону и 19-байтовое положение 3D-вида, индексы параметров/памяти, адреса, длины, порядок байтов и контрольные суммы.
- Начальный `00` относится к UART-сеансу, поэтому исключается только при сравнении BIN. Его однократную отправку отдельно проверяет виртуальный порт.
- Более 1000 случайных и половинных контрольных векторов Python проверяют курс, высоту, `yscreen`, смещения битов и итоговые пакеты C++.
- Проверяются четверти метра, дробные координаты, сохранение/загрузка, undo/redo и резервные биты. Переход через все четыре края и через угол сохраняет работу автопилота и дробное перемещение.
- Проверяются точные и ускоренные клавиши, сохранение обычного ввода чисел, квадратность экрана, отсутствие пересечений органов управления при разных размерах. Компактные панели, список с длинными именами, окна настроек и экспорта шрифтов, предупреждения симулятора и главное окно проверяются отдельно.
- Проверки окон используют временные настройки и не изменяют настройки пользователя. Ограничение времени в CTest прерывает зависшую проверку; тест модели получает векторы только после успешного сравнения Python.
- На Unix виртуальный последовательный порт проверяет сеанс, смену скорости, неизмененные маски, интервал и режим 0. В macOS используются стандартные скорости 57600/115200, поскольку PTY не поддерживает нестандартную скорость 921600. На Windows эта проверка пропускается; побайтовые проверки выполняются.
- Ошибочные XML с удаленными псевдонимами и старыми полями/разрядностями создаются из свежего примера. Проверка требует код возврата 1, сообщение об ошибке и отсутствие выходного BIN; аварийное завершение приложения не считается правильным отказом.
- Каждый запуск редактора сохраняет команду, код возврата, stdout и stderr в `*.bin.log`. При неожиданном результате эти сведения также выводятся в CTest. Пока проверки в GitHub Actions отключены, диагностические файлы доступны при локальном запуске.
- Проверяются строгие имена `aviahorizont` и `dashline`, отказ от псевдонимов и старых полей, сохранение открытой сцены при ошибке загрузки.
- Статические и вращающиеся PNG/SVG проверяются при углах 0°, 90°, 180°, 270°, 360°: маска не меняется, тип определяется при импорте. Проверяются знаковые sin/cos, копирование, история и повторная загрузка.
- Группы не создают дубликатов; видимость и замочки не меняют аппаратный enb. Единый XML сохраняет прежние аппаратные разделы и кодировку, добавляя настройки в `<editor>`. Проверяются восстановление редакторских флагов, групп, слоёв, исходников и вида холста, а также атомарный отказ при повреждении или отсутствии `<editor>`. Положение стороны 3D-вида передается в пакет из текущей сцены.
- Проверяются создание, переименование, цвета, дублирование, объединение и удаление слоёв, история, группы и вставка на рабочий слой. Проверяются множественное выделение слоёв через Ctrl/⌘ и Shift, объединение без диалога одной операцией истории, сохранение порядка объектов и размеров кнопок при уменьшенных иконках. Отдельно проверяются общие свойства, смешанные значения, атомарный отказ массового изменения, отсутствие изменений аппаратных разделов XML от метаданных слоёв, восстановление при загрузке и компоновка узкой панели.
- Проверяются выбор мышью с Shift/Ctrl, замочки объектов и групп, высота вертикальной панели и прокрутка, русский перевод цветового диалога из встроенного `qtbase_ru.qm`.
- Проверка изображения самолета во всех четырех углах карты подтверждает постоянство центра при смене курса и высоты. Самолет и радар берутся из отдельных SVG; радар обрезается границами карты.
- Для текста используется искусственный алфавит с известными масками, отрицательными bearing и парами кернинга. Проверяются координаты, BGR, отдельные слова SYMBOLs и общий RAMID для надписей одного шрифта, включая надписи на разных этапах каскада. Отдельно проверяется обрезка глифов у экрана с правильным шагом строки.
- Проверяются последний адрес SYMBOLs 16384, независимость лимитов SYMBOLs и STATICGROUP, суммарный предел 200 слов, 12-битные координаты и ошибки XML. Симулятор проверяет выбор прямоугольника по порядку RTL и чтение нескольких слов STATICGROUP.
- Проверка через виртуальный порт подтверждает, что после загрузки атласа замена строки в пределах резерва отправляет только изменённые слова. Очищенное поле сохраняет резерв, а слова отключаются. Превышение резерва блокирует обновление.
- Растровый предпросмотр редактора сравнивается с симулятором, XML сохраняется и загружается с последующим сравнением пакетов. Подмена init/data в сопроводительной аппаратной модели не меняет результат симулятора: рисование использует байты пакетов. BIN побайтово совпадает со сценой UART, а на Unix передача текста дополнительно проверяется через виртуальный порт.

## Границы проверки

Дополнительно проверяются прямые углы толстой обводки, проценты прозрачности и один шаг undo на перемещение ползунка. Объединение статических картинок проверяется по изображению (включая наложение), общему банку, отсутствию дубликатов в XML, загрузке и истории. Проверяются границы 8 init / 65 536 ячеек, отказ без изменения проекта, цветной блок памяти и сохранение исходного файла при отказе экспорта. События мыши с Shift/Ctrl проверяют пропорции и шаги поворота; проверяются кнопка, меню и записи горячих клавиш. Снимки `rectangle-corners.png`, `transparency-controls.png` и `memory-warning.png` сохраняются рядом с тестовым приложением.

Сравнение Python использует объекты, поддерживаемые его XML-загрузчиком. Преобразование font/text в SYMBOLs проверяют отдельные C++-сценарии с известными масками, координатами и байтами.

Знаковые `sin/cos` вращающихся объектов сериализуются через знаковое целое перед упаковкой в беззнаковое поле. Проверки охватывают обе отрицательные четверти.

Виртуальный порт проверяет программную последовательность, но не электрическую скорость, USB-драйвер платы, прием пакетов RTL или плавность реального изображения. Эту часть можно подтвердить только на ПЛИС. Значение `yscreen` передается непосредственно; формула перевода градусов тангажа в это поле не предполагается.

- В editor проверяются ссылки на аппаратные объекты, отсутствие дублированных параметров/масок/имён файлов для экспортируемых объектов и восстановление из изменённого init. Полные данные отключённых объектов сохраняются только в editor. Проверяется повторный цикл выключения/включения экспорта для текста и изображений, включая асимметричную вращаемую маску с сохранением центра. Пакеты не меняются; повторная запись после восстановления с точностью init стабильна.
- Проверяются глобальные настройки 8 init / 65 536 пикселей и применение изменённых ограничений к компиляции/упаковке. Симулятор проверяет реальные байты и контрольные суммы, отклоняет неверные длины и воспроизводит приоритет прямоугольников внутри STATICGROUP.

- Генератор `tube_config_pkg.sv` проверяется по типам enum, порядку, количеству этапов/слов, RAMID и соответствию адресам пакетов. Проверяются несколько init STATICGROUP, разворачивание многослойного rotationobject, отдельный 3D-вид, все типы шаблона, предел 200 параметров, неизвестные типы и неверные ссылки на память.
- Проверяются атомарная запись конфигурации, сохранение профиля в editor, восстановление после открытия, отсутствие влияния слоёв/групп и значений параметров на профиль. Повреждённые метаданные не заменяют текущий проект.
- Проверяются положение кнопки экспорта сразу после UART, одинаковые размеры кнопок и иконок, всплывающее предупреждение о смене структуры и отмена экспорта. На Unix виртуальный UART подтверждает создание файла до передачи, продолжение при изменении параметров и остановку при смене структуры. Ошибка записи или отмена диалога не запускают порт. Проверяются компактный блок автоматического сохранения и отсутствие пересечений полей и пояснений. Снимки `fpga-controls.png`, `fpga-configuration-export.png`, `uart-configuration.png` и `fpga-configuration-mismatch.png` сохраняются рядом с тестовым приложением.
- Реальные нажатия клавиш проверяют режимы ПЛИС, запуск/остановку на основной и цифровой клавиатуре, экспорт конфигурации, плавающую и скрытую панель, слои, видимость/блокировку/экспорт строк объектов, переименование и автопилот. Для глобальных команд проверяются отсутствие конфликтов и присутствие в справочнике настроек. Снимок `hotkeys-fpga.png` показывает раздел настроек с сочетаниями ПЛИС.
