# XML проекта редактора, версия 1

Команды **Сохранить** и **Сохранить как** записывают единый XML в прежней кодировке windows-1251. К прежним аппаратным разделам добавлен `<editor>`:

```xml
<project name="Приборная панель" width="1024" height="768" bgcolor="#000000">
    <parameters>…аппаратные схемы без изменения порядка полей…</parameters>
    <objects>…скомпилированные объекты ПЛИС…</objects>
    <editor version="1">
        <workspace>…</workspace>
        <layers>…</layers>
        <scene order="front-to-back">…</scene>
        <groups>…</groups>
        <resources>…</resources>
    </editor>
</project>
```

Содержимое `<editor>` — полная редактируемая сцена. Она восстанавливается непосредственно из этого раздела, а не из аппаратного растра. Поэтому сохраняются исходные типы объектов, дробные значения, точная прозрачность и объекты с отключённым экспортом. Скрытие на холсте и фильтр слоёв не исключают объекты из проекта.

## Рабочая область

```xml
<workspace canvas-width="1024" canvas-height="768" background="#ff000000"
           show-grid="true" grid-step="20" grid-color="#3778b4c8"
           snap-to-canvas="true" snap-to-grid="false" snap-to-objects="true"
           canvas-guide-color="#d2ff5c7a" grid-guide-color="#d256d3ff"
           object-guide-color="#dcffca58">
    <project-name>Приборная панель</project-name>
    <view scale="1.5" offset-x="-24.5" offset-y="16"
          proportional-resize="true" rotation-snapping="false"/>
</workspace>
```

Здесь находятся точный фон RGBA, размер и имя проекта, сетка, её шаг и цвет, все три режима привязки и цвета направляющих, масштаб, смещение просмотра, сохранение пропорций и шаг поворота. Числа с плавающей точкой записываются с 17 значащими цифрами, без округления под ПЛИС. Цвета — `#AARRGGBB`. Заголовок проекта и аппаратная часть используют прежние представления размеров и BGR-фона; при чтении проверяется согласованность с `<workspace>`.

Параметры сетки и направляющих в окне общих настроек служат начальными значениями нового проекта. Сохранённый проект восстанавливает собственные значения независимо от текущих общих настроек.

## Слои

```xml
<layers active-id="2" show-all="true" next-id="4">
    <layer id="1" selection-color="#ff00c8f0"><name>Фон</name></layer>
    <layer id="2" selection-color="#ffff5c7a"><name>Индикация</name></layer>
    <layer id="3" selection-color="#ffffca58"><name>Пустой слой</name></layer>
</layers>
```

Порядок элементов сохраняет порядок строк панели. Сохраняются пустые слои, идентификаторы, имена, цвета выделения, активный слой, режим «Все слои» и следующий идентификатор. Каждый объект должен ссылаться на существующий слой. Идентификаторы и имена слоёв уникальны.

## Сцена и флаги объектов

```xml
<scene order="front-to-back">
    <object id="object-1" type="rectangle" export-tag="rectangle_a" layer-id="2">
        <name>Сигнализация</name>
        <flags visible="false" selection-locked="true" export-enabled="true"
               resize-locked="false" imported-hardware="false">
            <restriction-hint/>
        </flags>
        <parameters enabled="true" x="32.25" y="40" width="120" height="80"
                    fill="#80ff5c7a" stroke="#ffedf7fb" stroke-width="2"
                    alpha="128" explicit-alpha="true"/>
    </object>
</scene>
```

`front-to-back` означает порядок от переднего плана к заднему, соответствующий списку объектов редактора. `id` связывает объекты с группами внутри файла; он не является индексом аппаратного объекта. Соответствие аппаратным объектам может быть «один ко многим», например для цветного изображения. `export-tag` сохраняет исходный аппаратный тип, включая вариант `rectangle_a`.

Флаги означают видимость в редакторе («глазик»), запрет выделения («замочек»), участие в экспорте, запрет изменения размера и признак аппаратного импорта. Последние два сохраняют ограничения редактирования импортированных объектов. Пользовательское имя и текст ограничения хранятся текстовыми узлами; строки с CR/CRLF имеют `encoding="base64-utf8"`, чтобы XML-нормализация не изменила переводы строк; пустое имя означает стандартное имя по типу. Аппаратная видимость `enabled` хранится отдельно от «глазика».

Редакторские типы и их содержимое:

| `type` | Содержимое `parameters` |
| --- | --- |
| `rectangle` | Геометрия, заливка, обводка, толщина, точный alpha и explicit-alpha, аппаратное включение. |
| `dashline` | Обе конечные точки, цвет, период, длина, фаза и толщина штрихов, аппаратное включение. |
| `RibonScale` | Границы, начальное смещение, период, толщина, цвет, аппаратное включение. |
| `aviahorizont` | Центр и область, цвета земли/неба/линии, толщина, sin/cos, аппаратное включение. |
| `layer3d` | Полное исходное слово init с резервными битами и состоянием самолёта, выбор стороны холста. |
| `image` | `kind="static"` или `kind="rotating"` на object; исходник, его формат и имя, точная геометрия и угол, автоцвет, цвет маски, список исходных цветов и настроек каждой цветовой маски. |
| `staticgroup` | Номер группы, все состояния с координатами, размерами, адресами, цветом и enabled; список масок. |
| `rotationobject` | Геометрия и центр, sin/cos, цвет, enabled, маска и полный список аппаратных состояний с исходной точностью. |
| `text` | Текст с пробелами и переводами строк, шрифт, размер, индекс, дополнительные символы и алфавиты экспорта; признак ограничения атласом, сам атлас при его наличии, состояния и маски. |

Для исходного текста сохраняется возможность менять шрифт и размер; открытие проекта не превращает его в импортированный аппаратный текст. Исходные SVG и растровые изображения сохраняются в самом файле, поэтому исходные внешние файлы не нужны для повторного открытия.

## Редакторские группы

```xml
<groups next-id="2">
    <group id="1">
        <name>Основные приборы</name>
        <member ref="object-1"/>
        <member ref="object-3"/>
    </group>
</groups>
```

Сохраняются имя, идентификатор, участники и счётчик новых групп. В группе минимум два разных объекта; отсутствующие ссылки и участие объекта в нескольких редакторских группах считаются ошибкой. Общие «глазик», «замочек» и экспорт группы определяются по флагам её участников, поэтому противоречивых дублирующих флагов у группы нет.

## Ресурсы

Маски и исходные изображения ссылаются на общий раздел ресурсов:

```xml
<source ref="resource-1"/>
<mask ref="resource-2"/>
<font-atlas ref="resource-3"/>
```

```xml
<resources>
    <binary id="resource-1" encoding="base64" media-type="image/svg+xml" sha256="…">…</binary>
    <binary id="resource-2" encoding="base64" media-type="image/png" sha256="…">…</binary>
    <font id="resource-3" index="0" size="14" volume="…">
        <name>Arial</name>
        <mask-data>…уровни 0–7…</mask-data>
        <order><glyph code="65"/>…</order>
        <glyphs>…все метрики и маски символов…</glyphs>
        <kerning><pair left="65" right="86" delta="-1"/>…</kerning>
    </font>
</resources>
```

Двоичные ресурсы дедуплицируются по типу и SHA-256, шрифты — по полному содержимому атласа. PNG сохраняет уровни масок без потерь. SHA-256 проверяется при чтении. Пустой `ref` маски означает отсутствие изображения. Шрифтовой ресурс сохраняет также порядок символов, ширины, высоты, advance, bearing, ascent/descent, offset, literal/code, размер и enabled каждого символа, маски и кернинг.

## Загрузка и целостность

- `<editor version="1">` обязателен при открытии проекта. Миграции старых XML без настроек редактора нет.
- Формирование `<project>`, `<parameters>`, `<objects>`, всех `<init>` и `<data>`, их порядок и кодировка не изменены. Настройки записываются только внутри нового `<editor>` в том же файле. Отдельного варианта XML и команды аппаратного экспорта в меню нет; `--export-xml` выполняет такое же сохранение проекта без открытия окна.
- `buildCompiledFpgaXml()`, BIN/UART и симулятор используют аппаратные данные. Метаданные редактора не добавляются в пакеты и память ПЛИС.
- При открытии сначала проверяется весь документ, версия, ссылки, идентификаторы, числовые значения и ресурсы. Повреждение или неизвестная версия не приводят к частичной загрузке либо незаметной потере настроек: текущий открытый проект сохраняется.
- Запись через QSaveFile заменяет файл только после успешного завершения. Ошибка записи сохраняет предыдущий файл.
- Раскладка окон, тема, автозагрузка последнего файла и настройки подключения UART принадлежат приложению/компьютеру. Буфер обмена, история отмены, временное выделение, жесты и работающие таймеры симуляции — состояние текущего сеанса. Они не входят в XML проекта; открытие файла не запускает передачу по UART.
