# AvionixDesigner

AvionixDesigner — редактор кадров на C++ и Qt для графического контроллера на базе ПЛИС. Приложение позволяет собирать интерфейс из объектов, редактировать их параметры и сохранять кадр в XML со схемами и порядком полей, необходимыми контроллеру.

**Разобраться в коде:** [руководство разработчика в папке docks](docks/README.md) — архитектура, карта классов, создание объектов, история, XML, пакеты, UART, симулятор и добавление новых возможностей.

## Возможности

- Прямоугольники, штриховые линии, ленточные шкалы, авиагоризонт, текст и импорт изображений.
- Выделение, группировка, выравнивание, изменение порядка объектов, отмена и повтор действий.
- Слои редактора с цветами выделения и массовое редактирование общих свойств выбранных объектов.
- Сетка и привязки к холсту, сетке, краям/центрам объектов и равным промежуткам.
- Область 3D-вида и панель позиционирования самолета: координаты X/Y, курс, высота, блок тангажа (yscreen) и автопилот.
- Подготовка пакетов ПЛИС, сохранение бинарных данных, передача по UART и встроенный симулятор.
- Загрузка и сохранение XML, подготовка растровых масок и шрифтов для ПЛИС.

Разделы: [сборка](#сборка), [объекты и преобразования](#объекты-и-точные-преобразования), [горячие клавиши](#горячие-клавиши), [3D-вид](#работа-с-3d-видом), [UART](#uart), [XML](#xml-для-плис), [структура проекта](#структура-проекта), [проверки](#проверка-протокола-без-плис), [выпуск](#выпуск-новой-версии).

## Сборка

Требования:

- CMake 3.19 или новее.
- Компилятор с поддержкой C++17.
- Qt 6.5 или новее с модулями `Core`, `Widgets`, `Xml`, `Svg` и `SerialPort`.
- NSIS — для создания установщика Windows через CPack.

Локальная сборка:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug --parallel
```

Если CMake не находит Qt, укажите каталог установленного комплекта Qt через `-DCMAKE_PREFIX_PATH=/path/to/Qt/kit` при конфигурации.

Приложение можно запустить из Qt Creator, открыв `CMakeLists.txt`, либо из каталога сборки:

- macOS: `build/AvionixDesigner.app`.
- Linux: `build/AvionixDesigner`.
- Windows с Visual Studio: `build/Debug/AvionixDesigner.exe`.

Для сборки установочного пакета:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
cmake --build build --config Release --target package
```

CPack создает установщик NSIS для Windows, DMG для macOS или архив TGZ для Linux. Сценарий [Windows Release](.github/workflows/windows-release.yml) собирает и публикует установщик Windows; версию он берет из `CMakeLists.txt`.

## Объекты и точные преобразования

В меню «Объекты» и библиотеке доступны отдельные команды добавления статического и вращающегося изображения. Тип выбирается при добавлении: вращающееся изображение остаётся `rotationobject` и при угле 0°. Поддерживаются SVG и растровые изображения, читаемые установленной сборкой Qt.

Shift добавляет объекты к выделению, Ctrl переключает их выделение. «Сгруппировать» объединяет выделение в редакторскую группу для перемещения и выравнивания. Редакторские группы, слои, имена, глазики и замочки сохраняются в разделе `<editor>` XML проекта. Флажок экспорта определяет, будет ли объект включён в аппаратный раздел XML; аппаратная видимость отдельных состояний по-прежнему записывается в `enb`.

Панель **Вид → Слои** управляет слоями редактора: добавление, переименование по двойному щелчку, цвет выделения, дублирование вместе с объектами, объединение и удаление. Ctrl/⌘ добавляет слои к выделению или исключает их, Shift выделяет диапазон. Кнопка объединения сразу переносит объекты всех выделенных слоёв в активный слой, сохраняя его имя, цвет и порядок объектов; операция отменяется одним действием. «Все слои» показывает всю сцену; цвет рамки каждого объекта определяется его слоем. В остальных режимах холст и список объектов показывают выбранный слой. Над холстом расположен список выбора рабочего слоя, новые и вставляемые объекты попадают на него. В свойствах поле «Слой» переносит выбранные объекты на существующий слой. Слой с единственным 3D-видом нельзя дублировать, поскольку в проекте допускается только один 3D-вид.

При множественном выделении свойства показывают пересечение параметров выбранных объектов; для объектов одного типа доступны все их общие параметры. Различающиеся значения отмечаются как «Разные значения». Изменение применяется ко всему выделению одной операцией истории; при недопустимом значении весь набор остаётся без изменений. Слои, группы, флаги объектов, текст, параметры сетки и привязок, масштаб/смещение просмотра и режимы преобразований сохраняются в XML и восстанавливаются при открытии. Экспортируемые объекты восстанавливаются из init/data; изображения после открытия используют сохранённый растр. Объекты с отключённым экспортом хранят свои данные в editor. Полная структура описана в [разделе о метаданных проекта](#метаданные-проекта). Переключение слоя, цвет выделения и режим «Все слои» не влияют на аппаратный XML.

У прямоугольника «Прозрачность» задаётся от 0% (непрозрачно) до 100% (полностью прозрачно): число слева и ползунок справа. Поле открывается командой **Правка → Изменить прозрачность** (`Ctrl+Alt+T`). На ПЛИС промежуточные значения округляются до восьми уровней `alph`; для полной прозрачности передаётся `enb=0, alph=0` в `rectangle_a`. Обводка и заливка используют общую прозрачность. Углы обводки прямые, толщина `a` отсчитывается снаружи заливки, как в аппаратном модуле.

Выберите статические изображения или существующие staticgroup и нажмите кнопку на боковой панели либо **Объекты → Объединить в staticgroup** (`Ctrl+Alt+G`). Результат — один аппаратный объект с общими data и последовательными адресами масок, по умолчанию до 8 init и 65 536 ячеек (лимиты задаются в глобальных настройках). Считаются все цветовые слои, а не только число картинок. Текст и вращающиеся объекты не объединяются. Операция сохраняет положение, порядок выбранных слоёв и поддерживает undo/redo; при нехватке памяти или изменении наложения промежуточных объектов объединение отклоняется. Флаги видимости и экспорта у исходных объектов должны совпадать. Иконка команды находится в `res/icons/selection/merge-static.svg`.

Предупреждения памяти показаны цветным блоком в свойствах, числовые сведения остаются в таблице. **Объекты → Проверить память ПЛИС** (`Ctrl+Alt+M`) проверяет экспортируемые растровые объекты. Для редактируемых изображений показывается предупреждение о существующем автоматическом уменьшении при экспорте. Переполнение готового staticgroup или rotationobject блокирует XML/BIN/UART с сообщением: пределы — 65 536 ячеек / 8 init и 2048 тайлов соответственно.

При перетаскивании ручки размера удерживайте **Shift**, чтобы сохранить пропорции. Для поворота **Shift** задаёт шаг **15°**, **Ctrl** — **90°**. Постоянные режимы включаются в меню «Правка»: **Сохранять пропорции** (`Ctrl+Shift+P`) и **Поворот с шагом 15°** (`Ctrl+Shift+R`). Все сочетания перечислены в **Настройки → Горячие клавиши**. Текст и готовые растровые группы сохраняют прежнее пропорциональное масштабирование; ограничения редактирования импортированных объектов остаются в силе.

На холсте **стрелки** перемещают выделенные объекты на **1 пиксель**, **Shift + стрелки** — по умолчанию на **10 пикселей**. Ускоренный шаг меняется в **Настройки → Общие → Шаг Shift + стрелки** (1–10 000 пикселей) и сохраняется между запусками. Привязки не меняют точный шаг стрелок; границы холста учитываются для всего выделения. При фокусе в поле ввода стрелки управляют этим полем.

При включённой **привязке к объектам** (`Shift+O`) перетаскиваемый объект автоматически притягивается к положению с равными промежутками: между двумя соседями либо при продолжении строки/колонки с любого конца. Оба промежутка отмечаются размерными стрелками с расстоянием в пикселях. Учитываются внешние границы объектов, включая обводку, и размеры групп; скрытые объекты и невидимые слои не участвуют. Порог притяжения — 8 экранных пикселей независимо от масштаба. Подписи и стрелки видны только во время перетаскивания и не экспортируются в ПЛИС.

Удерживайте **Shift после начала перетаскивания**, чтобы двигать выделение только по горизонтали или вертикали. **Alt** временно отключает привязки при перемещении; отпускание клавиши сразу возвращает их, сохраняя настройки проекта. Весь жест, включая переключение модификаторов, отменяется одним Undo.

**Вставить** (`Ctrl+V`) размещает центр скопированного объекта или общего габарита группы под курсором с учётом масштаба и панорамирования. У края холста весь набор смещается внутрь с сохранением взаимного расположения. Если курсор находится вне рабочей области, используется центр холста.

Числовые поля свойств, размеров холста и настроек принимают арифметические выражения: `+`, `-`, `*`, `/`, скобки и унарные знаки. Например, `(1920 - 80) / 2` даёт `920`. Дробную часть можно отделять точкой или запятой. Вычисление выполняется по **Enter** или при завершении редактирования; в проект попадает числовой результат. В целочисленных полях со стрелками дробный результат округляется; целочисленные свойства аппаратных модулей сохраняют свои ограничения. Некорректные выражения, деление на ноль и выход за допустимый диапазон отклоняются. Содержимое текстовых объектов остаётся обычным текстом.

Габариты и привязки прямоугольника включают видимую внешнюю обводку; параметры XML `x0/y0/w/h/a` сохраняют прежний смысл. Сетка рисуется поверх объектов, включая авиагоризонт, а маркеры выделения — поверх сетки.

### Центр вращения в редакторе

У выделенного вращающегося изображения (`rotationobject`, включая импортированные вращающиеся изображения) показана метка-перекрестие центра вращения. **Ctrl+Alt + ЛКМ** внутри объекта устанавливает её в точку щелчка; на macOS это **⌥⌘ + ЛКМ**. Установка метки поддерживает Undo/Redo и не сдвигает изображение, не меняет аппаратные `init/data` и пакеты ПЛИС.

Последующий поворот ручкой или через поле угла выполняется вокруг выбранной точки. Метка следует за перемещением и изменением размера объекта; жест поворота начинается без скачка угла. Она сохраняется в `<editor>` и восстанавливается даже после аппаратной обрезки прозрачных полей маски. В зависимой симметричной копии центр редактируется через исходник; при отсоединении копии её центр отражается вместе с изображением.

### Симметрия объектов

Две кнопки на вертикальной панели рабочей области создают симметрию относительно вертикальной или горизонтальной оси. Выберите исходные объекты: прямоугольники, штриховые линии, шкалы, статические или вращающиеся изображения и маски. Текст, авиагоризонт, 3D-вид и зависимые копии не поддерживаются. Для всего выделения создаётся одна ось через центр холста; её можно перетаскивать за линию или центральную ручку. Ось проходит через весь холст, учитывает масштаб и панорамирование, а её положение ограничивается границами копий.

Изменения исходников сразу отражаются в копиях. Зависимые копии имеют название «Имя исходника — копия» и значок копии справа от имени в списке. Геометрия меняется через исходник. Флажок аппаратного экспорта у копии снят и заблокирован: до отсоединения она хранится только в `<editor>`, отображается в редакторе и не попадает в ПЛИС или аппаратный симулятор.

Нажатие на значок копии превращает её в обычный независимый объект с текущей отражённой геометрией и масками. Значок исчезает, экспорт включается и становится доступным. Связь можно вернуть через Undo; отдельного переключателя обратного подключения нет. После отсоединения последней копии ось исчезает. При удалении исходника удаляются его зависимые копии. Создание, отсоединение и перетаскивание оси поддерживают Undo/Redo; Esc во время перетаскивания оси отменяет жест.

Оси и связи сохраняются внутри `<editor>` и восстанавливаются при открытии XML. Подробности формата и поведения — в [описании симметрии](docs/MIRROR_PROPOSAL.md). SVG-заглушки новых значков находятся в `res/icons/selection/symmetry-vertical.svg`, `symmetry-horizontal.svg` и `res/icons/list/symmetry-copy.svg`.

## Работа с 3D-видом

Добавьте объект «3D вид» из библиотеки объектов, чтобы включить панель позиционирования самолета. Область 3D-вида закрепляется у левого или правого края холста; сторона выбирается в свойстве «Положение».

Координаты X и Y задаются в **точках карты от 0 до 8191**, с шагом **1/64 точки**. По эталонному [All_together.py](checks/protocol/All_together.py) одна точка равна 32 м, один raw-шаг координаты — 0,5 м. X увеличивается вправо, Y — вверх. Весь диапазон показан на одной области без переключения квадратов. При выходе за край самолет переходит на противоположную сторону, сохраняя остаток перемещения; автопилот продолжает работать. Переход действует по обеим осям, в том числе по диагонали. Панель и объект 3D-вида отображают одно состояние модели.

Курс соответствует формулам Python: **0° — +X, 90° — +Y**. Поле допускает дробные градусы, шаг ввода — 0,05°. Автопилот сейчас использует 1400 км/ч и фактически прошедшее время, обновляя положение примерно раз в 16 мс. Дробное перемещение сохраняется и не округляется до целых точек.

Высота вводится с шагом **0,25 м** в рабочем диапазоне **0…16383,75 м**. Колесо на ползунке меняет высоту на 0,25 м, Shift + колесо — на 10 м, Page Up/Page Down — на 100 м. Отрицательные высоты из XML сохраняются, поле ввода расширяется до импортированного значения. Ползунок остается в положительном диапазоне.

Блок в панели называется **«Тангаж»** для удобства управления, но поле остаётся непосредственно `yscreen`, без преобразования в градусы: 0…1023. В XML, пакетах и программной модели используется только имя `yscreen`. Новый 3D-вид получает настройки рабочего примера Python: высота 16000 м, курс 45°, `yscreen = 1023`. Другие названия полей и прежние схемы XML не поддерживаются.

Клавиши работают при фокусе в панели позиционирования, например после щелчка по экрану или крутилке. Числовые поля сохраняют обычное редактирование текста. Полный список также доступен в **Настройки → Горячие клавиши**.

| Управление | Точный шаг | С зажатым Shift |
| --- | --- | --- |
| ← / → | Курс ±0,05° | ±1° |
| ↑ / ↓ | Тангаж ±1 единица yscreen | ±10 |
| + / −, также = | Высота ±0,25 м | ±10 м |

На основной клавиатуре «=» позволяет набирать высоту точным шагом, Shift+= — ускоренным. Клавиша «+» цифрового блока работает напрямую. Shift ускоряет также колесо регуляторов и кнопки тангажа.

Экран панели всегда квадратный. Размер содержимого панели ограничен диапазоном 800×360…1600×900 логических пикселей; элементы управления масштабируются по доступному месту. Компактные панели библиотеки, параметров холста и ПЛИС переносят кнопки на новые строки, а при недостаточной высоте показывают прокрутку. Вертикальная панель действий также прокручивается, не увеличивая минимальную высоту всего редактора.

## UART

Порт открыт на весь сеанс. В окне запуска отдельно задаются **скорость загрузки** (по умолчанию 921600 бод), **скорость управления** (115200 бод) и интервал отправки (20 мс).

1. Один раз отправляются начальный байт `00`, параметры и маски сцены, затем команда стороны 3D-вида.
2. Перед сменой скорости отправитель дожидается завершения передачи. Все операции порта выполняются в отдельном потоке и не блокируют движение самолета и интерфейс.
3. Дальше отправляются короткие пакеты положения 3D-вида. Если растровые банки прежние, передаются только изменившиеся слова параметров и команда стороны 3D-вида при её изменении. При изменении банка передаётся комплект сцены.
4. Очередь содержит только последнее ожидающее положение. Старые положения не накапливаются за медленным UART.

Интервал **0** означает отсутствие дополнительной паузы после готовности передатчика. Положительное значение задает минимальное время между началами пакетов положения. Для 8N1 пакет положения из 30 байт при 115200 бод занимает минимум около 2,60 мс; реальная частота зависит от драйвера и USB-UART. Режим 0 не означает мгновенную передачу.

### Конфигурация аппаратного конвейера

Команда **Объекты → Экспорт конфигурации ПЛИС** (`Ctrl+Alt+E`) и кнопка с иконкой файла справа от UART в панели **Управление ПЛИС** создают `tube_config_pkg.sv`. В диалоге выбирается путь сохранения. Ошибки подготовки и записи выводятся во всплывающих окнах.

Перед каждым запуском UART файл сохраняется автоматически по пути из диалога подключения. Для конфигурации в диалоге оставлены уведомление об автоматическом сохранении, поле пути и кнопка «Обзор» (`Alt+O`). Список портов обновляется кнопкой «Обновить» (`Alt+R`). Порт открывается только после успешной записи. Отмена диалога или ошибка записи отменяет запуск передачи. По умолчанию предлагается `tube_config_pkg.sv` рядом с XML проекта; для несохранённого проекта используется последняя выбранная папка.

Генератор получает ту же `FpgaHardwareScene`, что и упаковщик пакетов. `N_STAGES` задаёт число аппаратных этапов, `STAGE_TYPE` — их типы и порядок, `STAGE_PARAM_COUNT` — количество 150-битных слов, `STAGE_RAMID` — идентификаторы банков памяти. Для этапов без масок RAMID равен нулю. Статические изображения используют `TYPE_STATICGROUP`, текст использует `TYPE_SYMBOLs`. Оба модуля получают вектор слов. Объекты с однословным аппаратным интерфейсом разворачиваются в последовательные этапы. `RibonScale` соответствует `TYPE_SPEEDSCALE`. 3D-вид использует отдельную команду UART. Редакторские слои и группы на конфигурацию не влияют.

`PARAM_ARRAY_SIZE` фиксирован и равен **200**. При превышении суммарного числа параметров, пустом конвейере, неизвестном типе, неверных индексах или банках файл не создаётся. Имена и значения восьми enum соответствуют шаблону, включая `TYPE_RECTANGLEa` и `TYPE_SYMBOLs`. Экспорт выполняется через QSaveFile: ошибка не повреждает существующий файл и не заменяет сведения о последнем успешном экспорте.

Последняя экспортированная структура сохраняется в `<editor>/<fpga-configuration>` при сохранении проекта. При экспорте или запуске UART редактор сравнивает её с текущей сценой. В сравнении участвуют типы и порядок этапов, число слов и RAMID; значения параметров и содержимое масок не учитываются. Поэтому изменение цвета, координат или текста не требует нового файла, пока аппаратная структура сохраняется. При расхождении перед диалогом выбора пути выводится всплывающее предупреждение о необходимости нового `.sv` и пересборки прошивки ПЛИС. Возврат к прежней структуре снимает предупреждение; новый успешный экспорт обновляет сохранённую структуру.

Если состав конвейера изменился во время UART-сеанса, передача останавливается с предупреждением. Редактирование проекта остаётся доступным.

Файл является исходником конфигурации для сборки ПЛИС. Приложение не запускает сборку или программирование платы и не подтверждает соответствие загруженного битстрима. Ёмкость растровой памяти и аппаратные модули задаются отдельно в проекте ПЛИС.

## XML для ПЛИС

Сохраняется единый XML в прежней кодировке Windows-1251: `<project name="…" width="…" height="…" bgcolor="#BBGGRR">`, затем `<parameters>` с используемыми схемами, `<objects>` с объектами и раздел настроек `<editor>`. Аппаратные теги, поля, порядок и формат init/data не изменены. Названия тегов и полей чувствительны к регистру; в частности, `RibonScale`, `Enable` и `Color` записываются именно так.

При импорте схемы исходного файла должны точно совпадать с [реестром схем](src/schema/FpgaSchemaRegistry.cpp): порядок, имена, смещения и размеры полей проверяются до замены открытого проекта. Поддерживается один текущий формат без псевдонимов: `aviahorizont`, `dashline`, `staticgroup`, `rotationobject`, `rectangle`, `rectangle_a`, `RibonScale`, `layer3d`, `font`, `text`. При сохранении `<parameters>` и `<init>` используют тот же реестр. Документация аппаратных модулей и Verilog находятся в [docs](docs/); исторические XML из документации могут не соответствовать текущему строгому формату.

Общие правила для таблиц ниже:

- Биты нумеруются от младшего, диапазоны `[старший:младший]` включают обе границы. Все текущие слова `<init>` имеют 150 бит и 38 HEX-символов; два неиспользуемых старших бита HEX-контейнера равны нулю.
- `uN` — беззнаковое целое от 0 до `2^N − 1`; `sN` — знаковое целое в дополнительном коде от `−2^(N−1)` до `2^(N−1) − 1`. Отрицательные значения записываются младшими N битами дополнительного кода.
- Дробные значения используют **фиксированную точку**, а не IEEE 754: число умножается на масштаб и округляется до целого. Для 3D-вида ровная половина округляется к четному, как в Python `round`. Например, высота −0,25 м — это raw = −1, в 17 битах `0x1FFFF`.
- Цвет — `u24` в порядке BGR: `[23:16]` — B, `[15:8]` — G, `[7:0]` — R. Например, RGB `#123456` упаковывается как `0x563412`. Прозрачность хранится отдельно.
- `padding` — резерв. У новых слов он нулевой; 3D-вид сохраняет импортированные резервные биты.
- Пиксельные поля геометрии целочисленные. Для 12-битных беззнаковых координат предел — 4095; для знаковых 12-битных смещений — −2048…2047. Пределы полей следует учитывать при отладке больших объектов: не все редакторские операции ограничивают геометрию аппаратным диапазоном.

Объекты без маски содержат только `<init>`. `<staticgroup>`, `<rotationobject>` и `<font>` дополнительно содержат `<data>` с десятичными уровнями маски 0…7 через запятую: 0 — прозрачный пиксель, 7 — максимальная непрозрачность. В XML маски идут построчно, слева направо и сверху вниз; переупаковку в аппаратные блоки выполняет компилятор пакетов. У `<text>` в `<data>` находятся коды символов, а не пиксельная маска.

### 3D-вид — `<layer3d>`

Один `<init>`, без `<data>`. В XML размещается первым. В BIN/UART после обычной сцены идут два пакета типа `0x06`: сначала сторона (1 байт: left = 1, right = 0), затем положение (19 байт little-endian). Константы формата — [Layer3dFormat.h](src/fpga/model/Layer3dFormat.h).

| Поле | Биты | Формат | Назначение |
| --- | --- | --- | --- |
| `x` | `[18:0]` | u19 / 64 | X, 13 целых и 6 дробных битов; точки карты 0…8191 |
| `y` | `[37:19]` | u19 / 64 | Y, 13 целых и 6 дробных битов; точки карты 0…8191 |
| `course` | `[56:38]` | u19 × 360 / 2^19 | Курс в градусах: 0 ≤ угол < 360°; полный оборот равен 524288 единицам, шаг raw ≈ 0,000686646° |
| `height` | `[73:57]` | s17 / 4 | Высота −16384…16383,75 м, шаг 0,25 м |
| `yscreen` | `[83:74]` | u10 | Y экрана 0…1023, по умолчанию 1023; это не угол в градусах |
| `padding` | `[149:84]` | u66 | Резерв |

Поле высоты не теряет дробные биты при чтении, редактировании, отмене/повторе и сохранении. Дробные части координат и курса сохраняются при редактировании других полей. Сторона размещения 3D-вида сохраняется в разделе `<editor>` XML проекта, а в UART/BIN передаётся отдельной командой `0x06` с одним байтом.

### Прямоугольник — `<rectangle>`

| --- | --- | --- | --- |

| `colorb` | `[48:25]` | u24, BGR | Цвет рамки |

| `y0` | `[72:61]` | u12 | Y левого верхнего угла, пиксели |
| `w` | `[84:73]` | u12 | Ширина, пиксели |
| `h` | `[96:85]` | u12 | Высота, пиксели |
| `a` | `[108:97]` | u12 | Толщина рамки, пиксели |

### Прямоугольник с прозрачностью — `<rectangle_a>`

Один `<init>`, без `<data>`. Используется для прямоугольника с явной или частичной прозрачностью. Значение `alph = 0` означает 1/8 непрозрачности, а не полностью прозрачную заливку; отдельного значения нулевой непрозрачности в этом поле нет.

| Поле | Биты | Формат | Назначение |
| --- | --- | --- | --- |
| `enb` | `[0:0]` | u1 | Разрешение отображения |
| `color` | `[24:1]` | u24, BGR | Цвет заливки |
| `colorb` | `[48:25]` | u24, BGR | Цвет рамки |
| `alph` | `[51:49]` | u3 | Непрозрачность: аппаратный коэффициент `(alph + 1) / 8`, от 1/8 до 1 |
| `x0` | `[63:52]` | u12 | X левого верхнего угла |
| `y0` | `[75:64]` | u12 | Y левого верхнего угла |
| `w` | `[87:76]` | u12 | Ширина, пиксели |
| `h` | `[99:88]` | u12 | Высота, пиксели |

| `padding` | `[149:112]` | u38 | Резерв |

### Поворачиваемая маска — `<rotationobject>`

Один или несколько `<init index="…">` для аппаратных слоев и общий `<data width="…" height="…">`. Правая и нижняя границы определяют размер разностями `right − left`, `bottom − top`. Компилятор пакетов разбивает маску на тайлы 8×8 с дополнительной строкой и столбцом для интерполяции. Значения sin/cos ±1 записываются как ±65536 и помещаются в s18.

| Поле | Биты | Формат | Назначение |
| --- | --- | --- | --- |
| `enb` | `[0:0]` | u1 | Разрешение слоя |
| `color` | `[24:1]` | u24, BGR | Цвет маски |
| `xrot` | `[36:25]` | u12 | X центра вращения на экране |
| `yrot` | `[48:37]` | u12 | Y центра вращения на экране |
| `top` | `[60:49]` | s12 | Верхняя граница относительно центра вращения |
| `left` | `[72:61]` | s12 | Левая граница относительно центра вращения |
| `bottom` | `[84:73]` | s12 | Нижняя граница относительно центра вращения |
| `right` | `[96:85]` | s12 | Правая граница относительно центра вращения |
| `sq` | `[104:97]` | u8 | Количество тайлов по X: `ceil((right − left) / 8)`, до 255 |
| `sin` | `[122:105]` | s18 / 65536 | Синус угла поворота, 16 дробных битов |
| `cos` | `[140:123]` | s18 / 65536 | Косинус угла поворота, 16 дробных битов |
| `padding` | `[149:141]` | u9 | Резерв |

### Статическая маска / группа состояний — `<staticgroup>`

Один `<init index="…">` на состояние и один общий `<data>`. Атрибут `nomber` сохраняется с таким написанием. Пиксель `(x, y)` состояния находится в памяти по индексу `addr + y × w + x`; резервная/неиспользуемая память заполняется нулями. Не путать аппаратный объект с редакторской группировкой выделенных объектов.

| Поле | Биты | Формат | Назначение |
| --- | --- | --- | --- |
| `enb` | `[0:0]` | u1 | Разрешение состояния |
| `color` | `[24:1]` | u24, BGR | Цвет состояния |
| `x` | `[36:25]` | u12 | X левого верхнего угла |
| `y` | `[48:37]` | u12 | Y левого верхнего угла |
| `w` | `[60:49]` | u12 | Ширина маски, пиксели |
| `h` | `[72:61]` | u12 | Высота маски, пиксели |
| `addr` | `[88:73]` | u16 | Смещение маски в общей памяти, в элементах маски |
| `padding` | `[149:89]` | u61 | Резерв |

### Штриховая линия — `<dashline>`

Один `<init>`, без `<data>`. `dt` вычисляется по расстоянию между концами с округлением до целого. Значение +256 не помещается в s9: максимально положительный коэффициент равен 255/256. Это дает небольшую погрешность направления/длины, но не меняет знак направления. Длины больше 4095 не представимы положительным s13.

| Поле | Биты | Формат | Назначение |
| --- | --- | --- | --- |
| `Enable` | `[0:0]` | u1 | Разрешение отображения |
| `Color` | `[24:1]` | u24, BGR | Цвет линии |
| `xo` | `[36:25]` | u12 | X начала линии |
| `yo` | `[48:37]` | u12 | Y начала линии |
| `dt` | `[61:49]` | s13 | Длина линии; для прямого направления используются положительные значения 1…4095 |
| `a` | `[70:62]` | s9 / 256 | Коэффициент направления X: `round((x1 − x0) / dt × 256)`, ограничен −256…255 |
| `b` | `[79:71]` | s9 / 256 | Коэффициент направления Y: `round((y1 − y0) / dt × 256)`, ограничен −256…255 |
| `StepPow` | `[82:80]` | u3 | Период штриха равен `2^(raw + 1)`, то есть 2…256 пикселей |
| `Length` | `[90:83]` | u8 | Длина штриха минус 1: 1…256 пикселей |
| `Phase` | `[98:91]` | u8 | Фаза штриха, пиксели |
| `Width` | `[102:99]` | u4 | Толщина линии минус 1: 1…16 пикселей |

У `<init>` есть `index`, `literal`, `code`. Дополнительные `<kerning left="…" right="…" delta="…">` задают знаковую поправку расстояния между парой символов. Эти атрибуты и элементы не занимают биты init.

Атрибут `text` у `<init>` хранит читаемую строку для редактора. `font` и `text` остаются ресурсами XML; перед отправкой программа преобразует их в обычные статические параметры и растры, как описано ниже.

### Передача текста через SYMBOLs

Сохранение XML и подготовка аппаратной сцены разделены. XML сохраняет алфавит, метрики, пары кернинга и коды строк, чтобы его могли обрабатывать другие программы. На ПЛИС эти структуры напрямую не передаются: программа сама рассчитывает расположение букв.

1. [FontAtlasXml](src/text/FontAtlasXml.cpp) читает маски и метрики из XML и проверяет коды, размеры, смещения и ссылки на шрифты. Для созданного в редакторе текста [FontRasterizer](src/text/FontRasterizer.cpp) формирует те же растры и метрики, которые сохраняются в XML.
2. [TextLayout](src/text/TextLayout.cpp) рассчитывает позиции глифов по `advance`, знаковым `bearing_x/bearing_y` и парам кернинга. X/Y задают начало общего прямоугольника надписи. Qt рисует глиф с запасом, затем экспортирует прямоугольник полезных пикселей и корректирует bearing. Пробелы, табуляция и переводы строки задают пробельный шаг.
3. [FpgaSceneCompiler](src/fpga/compiler/FpgaSceneCompiler.cpp) назначает один RAMID каждому используемому атласу. Соседние надписи одного шрифта и размера входят в один этап `TYPE_SYMBOLs`. Если надписи разделены другими этапами, они остаются в каскаде и используют тот же RAMID. Текущий RTL выделяет BRAM внутри каждого экземпляра `SYMBOLs`, поэтому такие экземпляры получают одну и ту же загрузку UART каждый в свою BRAM.
4. Каждая позиция получает 150-битное слово с `enb`, BGR-цветом, `x`, `y`, `w`, `h` и `addr`. Например, «МАМА» получает четыре слова и использует по одному адресу для обеих «М» и обеих «А». Пробелы, невидимые символы и свободные позиции получают нулевые слова. Если правая граница экрана обрезает глиф по ширине, компилятор дописывает общий вариант маски с новым шагом строки в конец банка.
5. [FpgaPacketCompiler](src/fpga/packets/FpgaPacketCompiler.cpp) передаёт слова пакетами `0x03`, каждый банк — пакетами `0x04` по 1024 пикселя. Один уровень 0…7 занимает байт передачи. Базовые адреса соответствуют смещениям в XML-атласе. Коды символов, метрики и кернинг остаются в XML.

Свойство **Позиции ПЛИС (0 — авто)** задаёт фиксированную ёмкость поля. При нуле ёмкость берётся из длины строки на момент запуска UART, включая пробелы. Во время сеанса можно заменить строку символами из загруженного алфавита, укоротить или очистить поле. Редактор пересчитает позиции, адреса и флаги и отправит изменившиеся слова. Для более длинной строки требуется увеличить число позиций и обновить конфигурацию ПЛИС. Для другого шрифта или символа вне загруженного алфавита требуется заново загрузить сцену. Выбрать доступные буквы можно в свойствах экспорта шрифта.

В глобальных **Настройки → ПЛИС — STATICGROUP** задаются ёмкость банка (по умолчанию **65 536 пикселей / 64 КиБ передаваемых данных**) и число элементов группы (**8**). Ключи QSettings: `fpga/staticGroupPixels` и `fpga/staticGroupElements`. Проверки экспорта, объединение групп, сведения о памяти и подготовка статических изображений используют эти значения. Они не записываются в XML проекта. Настройка памяти ограничена 16-битной адресацией текущего протокола; изменение профиля программы не меняет прошивку платы.

Один банк SYMBOLs в текущем RTL вмещает **16 385 пикселей** (`bram[16384:0]`). Слова SYMBOLs входят в общий лимит **200** на конвейер. При переполнении экспорт сообщает требуемый и доступный ресурс. В XML `mask_size` глифа должен равняться `w × h` и помещаться в 12 бит, длина текста — не превышать 4095 кодов UTF-16.

Симулятор читает маски и параметры из байтов пакетов и проверяет заголовки, длины, контрольные суммы и границы памяти. Внутри этапа STATICGROUP или SYMBOLs RTL выбирает первый совпавший прямоугольник в порядке слов UART. У него может быть прозрачный пиксель, под которым другой символ этого этапа останется скрыт. Симулятор показывает предупреждение при пересечении прямоугольников SYMBOLs. Предпросмотр редактора смешивает маски всех глифов и в таком случае может отличаться.

### Метаданные проекта

Проект сохраняется одним XML в кодировке windows-1251. Аппаратные схемы, порядок полей init и представление data сохранены.

```xml
<project name="Панель" width="1024" height="768" bgcolor="#000000">
    <parameters>…схемы полей…</parameters>
    <objects>…только объекты с включённым экспортом, шрифты и текст…</objects>
    <editor>
        <workspace>…</workspace>
        <layers>…</layers>
        <symmetry>…оси зависимых копий, если они есть…</symmetry>
        <scene order="front-to-back">…</scene>
        <groups>…</groups>
        <resources>…ресурсы только отключённых объектов…</resources>
    </editor>
</project>
```

#### Данные объектов

Для включённого экспорта единственный источник геометрии, цветов, аппаратной видимости, параметров вращения и растров — соответствующие init/data в objects. Текст, шрифт, метрики и кернинг восстанавливаются из text/font. Эти данные не дублируются в editor. Геометрия после открытия имеет точность аппаратных полей.

```xml
<scene order="front-to-back">
    <object id="object-1" type="rectangle" export-tag="rectangle_a"
            layer-id="2" hardware-index="0">
        <name>Сигнализация</name>
        <flags visible="false" selection-locked="true" export-enabled="true"
               resize-locked="false" imported-hardware="false">
            <restriction-hint/>
        </flags>
    </object>
</scene>
```

`hardware-index` — индекс с нуля среди дочерних объектов objects, без font. Он не является индексом слова параметров UART. Каждая аппаратная запись должна иметь ровно одну ссылку из сцены. Цветное статическое изображение представлено одной записью staticgroup с несколькими init и общим data. В type="image" атрибут kind="static" или kind="rotating" сохраняет способ редактирования; растр берётся из аппаратной записи.

Для отключённого экспорта ссылки hardware-index нет. В editor сохраняется parameters с полными данными объекта, поскольку в objects этого объекта нет:

```xml
<object id="object-2" type="rectangle" export-tag="rectangle" layer-id="2">
    <name>Черновик</name>
    <flags visible="true" selection-locked="false" export-enabled="false"
           resize-locked="false" imported-hardware="false">
        <restriction-hint/>
    </flags>
    <parameters enabled="true" x="32.25" y="40" width="120" height="80"
                fill="#ffffffff" stroke="#00000000" stroke-width="0"
                alpha="255" explicit-alpha="false"/>
</object>
```

При включении экспорта параметры переходят в objects, а parameters внутри editor исчезает. При выключении выполняется обратное действие при следующем сохранении. Метаданные имени, флагов, порядка и связей со слоями/группами остаются в editor в обоих случаях. Выключенный глазик отличается от выключенного экспорта и от аппаратного enb.

Исходные имена файлов изображений не сохраняются. Для экспортируемого изображения исходный SVG/PNG не дублируется: после открытия используется растр из data. Для отключённого изображения сохраняется его источник или набор восстановленных растровых слоёв, достаточный для последующего включения экспорта. Параметры вращения берутся из init; при обрезке прозрачных полей сохраняются центр вращения и исходные sin/cos.

#### Режимы редактирования

У вращающихся объектов необязательный элемент `rotation-pivot` в записи сцены `<editor>/<scene>/<object>` хранит редакторский центр в атрибутах `canvas-x` и `canvas-y`. Это координаты холста; при восстановлении они переводятся в локальные координаты объекта. Внутри сеанса локальное представление позволяет метке следовать за преобразованиями объекта. Старые XML без этого элемента используют прежний центр вращения. Установка метки не переписывает аппаратные `xrot/yrot` и другие параметры `init`.

У текста text-options хранит режим ограничения импортированным атласом, выбор дополнительных символов, алфавиты экспорта и резерв позиций `symbol-capacity`. Строка, название и размер шрифта, метрики, маски и кернинг восстанавливаются из objects. Обычный текст после открытия позволяет менять строку, шрифт и размер. Для ограниченного атласа сохраняются его ограничения.

У 3D-вида left-anchored хранится в editor, потому что сторона размещения не входит в init и передаётся отдельной командой UART.

#### Рабочее пространство и связи сцены

workspace сохраняет имя, размер и фон проекта, сетку, привязки, цвета направляющих, масштаб и смещение вида, режимы изменения размеров и поворота. Заголовок аппаратного XML сверяется с workspace. Цвета редактора представлены как #AARRGGBB. Числа состояния сцены записываются с 17 значащими цифрами.

layers сохраняет порядок, идентификаторы, имена и цвета слоёв, активный слой, show-all и счётчик новых идентификаторов. Сохраняются и пустые слои. Каждый объект ссылается на существующий слой.

groups сохраняет идентификаторы, имена, участников и счётчик новых групп. Участники ссылаются на id объектов в scene. Порядок scene="front-to-back" соответствует списку объектов редактора. Флаги группы вычисляются по участникам.

Строки с CR/CRLF используют encoding="base64-utf8", чтобы нормализация XML не изменяла их содержимое. Имена могут содержать Unicode; пустое пользовательское имя означает стандартное имя типа объекта.

#### Ресурсы отключённых объектов

resources содержит PNG-маски, источники отключённых изображений и шрифтовые ресурсы отключённого текста. Двоичные данные кодируются base64, проверяются по SHA-256 и дедуплицируются по типу и содержимому. Маски восстановленных изображений хранятся отдельными растровыми слоями, чтобы выключение и повторное включение экспорта сохраняли данные масок.

Последний успешный экспорт аппаратного конвейера хранится в `fpga-configuration` как список `stage` с атрибутами `type` (значение enum), `param-count` и `ramid`. Здесь нет параметров объектов или копий растров. Отсутствие этого раздела означает, что конфигурация ещё не экспортирована.

#### Проверка целостности

Раздел editor обязателен при открытии проекта редактора.

Перед заменой открытой сцены проверяются аппаратный XML, ссылки, идентификаторы, числовые значения и ресурсы. Повреждённые данные оставляют текущий проект открытым. QSaveFile заменяет файл только после успешного сохранения.

BIN/UART и симулятор используют аппаратные данные; содержимое editor не передаётся в память платы. Глобальные ограничения STATICGROUP, тема, расположение окон, автозагрузка и настройки UART принадлежат приложению. История отмены, временное выделение и работающие таймеры не сохраняются. Открытие проекта не запускает передачу по UART.

### Изображения и редакторские группы

`ImageObject` не сохраняется отдельным аппаратным тегом `<image>`. Выбранный при добавлении статический тип экспортируется в `<staticgroup>`, вращающийся — в `<rotationobject>`, включая угол 0°. Для них действуют описанные выше поля и ограничения памяти. Редакторские группы служат для совместного выделения и управления объектами; собственных init/data у них нет. Команда объединения staticgroup создаёт реальный аппаратный объект и сохраняется в XML.

```text
│   ├── verify_fpga_packets.py      # Генерация сцен и сравнение BIN с Python
│   ├── All_together.py             # Неизменяемый эталон протокола
│   └── README.md                   # Запуск и границы автоматических проверок
├── docs/                           # Спецификации модулей и документация
│   ├── verilog/                    # Исходные реализации модулей ПЛИС
│   └── xml (исходные)/             # Исторические примеры аппаратного XML
├── tests/                          # Пользовательские проекты для ручных проверок
├── .github/workflows/
│   └── windows-release.yml         # Сборка и публикация установщика Windows
└── build/                          # Локальные результаты сборки, вне Git
    ├── verification/               # Созданные проверками XML, BIN и журналы
    └── checks/protocol/            # Тестовое приложение и снимки интерфейса
```

`ProjectManager` управляет документом, объектами, слоями, группами и историей. Классы из `objects/` отвечают за геометрию, свойства и отрисовку; `ObjectsManager` создаёт их по зарегистрированным именам. `FpgaSchemaRegistry` задаёт единую раскладку аппаратных полей. Глобальные настройки, включая ограничения STATICGROUP, находятся в `ApplicationSettings`.

При сохранении `ProjectManager` формирует аппаратные `init/data`, `EditorProjectXml` добавляет метаданные сцены, затем `QSaveFile` записывает единый XML. При открытии аппаратные разделы проходят проверку схем, после чего `EditorProjectXml` восстанавливает объекты и состояние редактора.

Путь BIN/UART и симуляции проходит через `ProjectManager → XML → FpgaCompiledDocument → FpgaSceneCompiler → FpgaHardwareScene → FpgaPacketCompiler → FpgaPacketBundle`. Транспорт и симулятор получают один и тот же набор пакетов. Модуль `text/` рассчитывает расположение глифов для предпросмотра и аппаратных слов SYMBOLs. Композиция целой строки используется в предпросмотре редактора.

В начале каждого C++-файла и перед определением класса, структуры или перечисления дано пояснение `Имя - назначение`. Комментарии к алгоритмам описывают ограничения формата, порядок слоёв и причины нетривиальных действий. Новые исходники включаются в `CMakeLists.txt`, ресурсы интерфейса — в `res/resources.qrc`.

Локальные `CMakeLists.txt.user`, каталоги сборки, кэши Python и файлы Finder исключены из Git. `FrameGUI/` и `docs/FrameGUI/` — локальные архивы вне текущей сборки. Содержимое `tests/` служит для ручных проверок; автоматические тесты создают собственные проекты в каталоге сборки.

## Проверка протокола без ПЛИС

Подробности и границы проверки — в [checks/protocol/README.md](checks/protocol/README.md). Нужны Qt Test и Python 3.10+. Эталон `All_together.py` и скрипт сравнения `verify_fpga_packets.py` находятся вместе в `checks/protocol/`; весь каталог должен попасть в коммит вместе с изменениями приложения. Для сравнения не нужны pyserial, keyboard, numpy или OpenCV: инструмент исполняет выбранные функции упаковки и XML-загрузчика с перехватом байтов вместо реального порта.

```bash
cmake -S . -B build -DAVIONIX_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug --parallel
ctest --test-dir build -C Debug --output-on-failure
```

Проверки создают четыре проекта `reference-right.xml`, `reference-negative-sin.xml`, `reference-negative-cos.xml` и `reference-negative-both.xml` в `build/verification/`, прогоняют каждый файл через Python и реальное приложение и сравнивают BIN целиком. Там же остаются пары `python-*.bin`, `editor-*.bin` и контрольные векторы положения. Готовые BIN не включаются в исходники.

Для отдельного экспорта без открытия окна:

```bash
# macOS; на Windows используйте build/Debug/AvionixDesigner.exe
build/AvionixDesigner.app/Contents/MacOS/AvionixDesigner --export-bin build/verification/reference-right.xml build/frame.bin
```

`--export-xml input.xml output.xml` выполняет обычное сохранение проекта с `<editor>` без открытия окна. Раздел `<editor>` обязателен при загрузке; XML без него не открывается как проект. Обе команды работают без подключения UART и используют временный профиль настроек. При обычном запуске редактор использует прежнее хранилище настроек пользователя; для отдельного диагностического профиля можно явно задать путь к INI-файлу в переменной `AVIONIX_SETTINGS_FILE`.

## Выпуск новой версии

Текущая версия сборки — **1.0.8** в `CMakeLists.txt`. Workflow получает номер непосредственно из `project(AvionixDesigner VERSION …)`.

1. Для каждого нового выпуска задайте новый `VERSION` в строке `project(AvionixDesigner VERSION …)`.
2. Соберите и проверьте приложение, затем закоммитьте изменения и отправьте их в `main` командой `git push origin main` (либо объедините pull request в `main`).
3. На GitHub откройте **Actions → Windows Release** и дождитесь успешного завершения. Workflow установит Qt и NSIS, соберет приложение и установщик.
4. Готовый файл **AvionixDesigner-1.0.8-windows-x64.exe** появится в **Releases → v1.0.8 → Assets**, а также среди артефактов запуска Actions. Тег и релиз создаются автоматически; вручную создавать тег не требуется. Проверки протокола в Actions временно отключены: после сборки сразу выполняется упаковка установщика. Локальные проверки можно включить через `AVIONIX_BUILD_TESTS=ON`.

Сборку также можно запустить вручную через **Run workflow** для ветки `main`. Версии должны быть уникальными: существующий workflow при повторе версии заменяет файл установщика в том же релизе, но существующий тег не переносит на новый коммит. Поэтому для нового набора изменений увеличивайте версию, а не переиспользуйте прежнюю.
