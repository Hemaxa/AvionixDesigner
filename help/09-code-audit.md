# 09. Результаты ревизии кода

[К оглавлению](README.md)

Проверено текущее дерево исходников после добавления автоматических равных промежутков. Это отчёт о конкретных проверках и изменениях, а не математическое доказательство отсутствия любых ошибок или недостижимого кода.

## Что проверено

- Все 129 файлов `.h`/`.cpp` в `src` перечислены в CMake. Записей о несуществующих исходниках не обнаружено.
- Перед определениями классов и структур проверены поясняющие комментарии: структурная проверка проходит для 118 определений типов, включая локальные и вложенные типы.
- Все 61 ресурс из `res/resources.qrc` существуют и имеют ссылки в коде/теме. Учтены динамические шаблоны имён SVG для слоёв и кнопок `yscreen`.
- Просмотрены регистрации фабрики, наследники `BaseObject`, обработчики панелей, цепочка XML → аппаратная сцена → пакеты и владение UART-портом.
- Выполнена дополнительная сборка Clang с `-Wall -Wextra -Wpedantic -Wunused-private-field`. Предупреждений о неиспользуемых функциях, переменных и приватных полях не обнаружено.
- Пройдены три проверки CTest: структура проекта, независимое сравнение пакетов с Python и интеграционные QtTest-сценарии. В QtTest — 87 успешных случаев без ошибок и пропусков.

При дополнительной сборке установленный Qt сообщает об устаревании `QImage::mirrored()` в нескольких существующих местах. Это используемый код отражения, а не мёртвые функции. API сохранён с учётом поддерживаемого проектом Qt 6.5; переход на более новый API требует соблюдения этой совместимости.

## Что изменено

`ProjectManager.cpp` уменьшился с 3413 до 1856 строк. Основная часть кода перенесена по ответственности, а не удалена как ненужная. Добавлена проверка полиморфных копий всех фабричных типов и перенаправления связей симметрии.

## Что не является лишним

- `checks/protocol/All_together.py` реально используется независимым сравнением пакетов. Наличие похожего алгоритма в C++ здесь намеренно: сравнение должно иметь отдельный эталон.
- Документация модулей, Verilog и исходные примеры в `docs` — справочные материалы, а не исходники GUI. Отсутствие их в CMake ожидаемо.
- SVG с именами `screen-y-*` и значки действий слоёв выбираются динамически. Поиск одного полного литерала дал бы ложный вывод об их неиспользовании.
- Виртуальные обработчики событий Qt вызываются системой событий. Отсутствие прямого вызова `mouseReleaseEvent()` в приложении не делает метод мёртвым.
- Сгенерированная сборка, настройки Qt Creator, системные `.DS_Store` и локальные копии `FrameGUI` не являются частью проверяемого дерева исходников приложения. Личные локальные копии и исходные документы не удалялись.

Неиспользуемых отслеживаемых C++-файлов и бесхозных ресурсов QRC по выполненным проверкам не найдено. Удалять рабочие файлы только ради уменьшения их количества оснований нет.

## Архитектурные особенности, которые остаются

`ProjectManager` остаётся крупным фасадом со слоями, группами, буфером и историей. `MainWindow` содержит связывание UI и часть команд, в том числе выравнивание. При дальнейшем росте эти области можно выделять отдельно по реальной задаче.

Многие параметры фигур пока публичные. Это упрощает существующие импорт/экспорт и настройку начальных значений, но позволяет обойти проверку и историю при прямом изменении поля. Пользовательские изменения следует проводить через `ProjectManager` и методы объекта. Полное закрытие всех полей потребует отдельного согласованного изменения доступа во всём проекте.

`EditorProjectXml` знает конкретные классы и вложенные типы менеджера: сериализация ещё связана с моделью проекта. `FpgaXmlExporter` и обработчики аппаратного формата также имеют ветвления по типам, потому что форматы модулей различаются. Полиморфное клонирование устранило одну из таких крупных цепочек; произвольная замена всех ветвлений не была целью ревизии.

Небольшие утилиты без состояния остаются функциями/пространствами имён. Сами по себе они не нарушают разделение ответственности. ООП не требует наследования для каждого преобразования числа.

## Пределы проверки

Компилятор и поиск ссылок не доказывают достижимость каждой публичной функции при всех действиях пользователя. Структурная проверка подтверждает наличие комментария, а его смысл требует чтения кода. Проверки интерфейса выполнялись с `offscreen`; физическая передача на реальную плату не выполнялась.

Аппаратные форматы и поведение приложения при рефакторинге должны сохраняться. Это проверено существующими сценариями XML, пакетным Python-эталоном, историей, клонированием, симметрией, текстом и автоматическими привязками. Следующие изменения следует проверять теми же командами из [главы 8](08-build-and-development.md).
