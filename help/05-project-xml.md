# 05. XML проекта и сохранение

[К оглавлению](README.md) · [Далее: пакеты и UART](06-fpga-and-uart.md)

## Две части одного документа

Проект сохраняется одним XML с аппаратным содержимым и метаданными редактора. Упрощённая схема ниже показывает назначение разделов, а не готовый файл для загрузки:

```xml
<project name="..." width="..." height="..." bgcolor="...">
    <parameters><!-- битовые схемы модулей --></parameters>
    <objects><!-- аппаратные объекты с init и, при необходимости, data --></objects>
    <editor><!-- сцена редактора, слои, группы, настройки и ссылки --></editor>
</project>
```

`FpgaXmlExporter` формирует аппаратные разделы. `EditorProjectXml` добавляет редакторскую часть. `ProjectXmlFile` занимается чтением/записью файла и кодировкой. `ProjectManager` координирует эти шаги и меняет текущий проект только после успешного чтения.

## parameters и init

`FpgaSchemaRegistry::fieldsForSchema()` возвращает поля в требуемом аппаратном порядке. `ParamSchema` — карта имени на смещение и ширину — удобна для обращения к полям, но порядок обхода карты не следует использовать как порядок XML.

`BaseObject::serializeParams()` отдаёт значения полей. Экспортёр создаёт HEX нужной длины, а `BitParser::inject()` записывает значения по битовым смещениям. `extract()` и `extractSigned()` выполняют обратное действие.

В аппаратном представлении слова параметров доводятся до 150 бит, передаваемых в 19 байтах. Упаковка UART описана отдельно в следующей главе.

Имена `RibonScale`, `rectangle_a`, `aviahorizont`, `layer3d` и написание аппаратных атрибутов нельзя исправлять по языковым соображениям: это имена формата. Цвет в аппаратных полях имеет порядок BGR; преобразование сосредоточено в `BitParser`.

## data и ресурсы

Параметрические фигуры могут обходиться без `data`. Маски статических/вращающихся объектов и шрифтов содержат уровни 0…7. Маска задаёт вклад объекта; цвет обычно задаётся в init.

`FpgaXmlExporter` подготавливает цветовые компоненты изображений, общий растр `staticgroup` и ресурсы шрифтов. Текст сохраняется через `font`/`text`, после чего аппаратный компилятор разворачивает его в SYMBOLs.

## Что хранится в editor

`EditorProjectXml::State` собирает имя/размер/фон, объекты и их порядок, слои, группы, параметры сетки/привязок, просмотр и профиль конфигурации ПЛИС.

У экспортируемых объектов геометрия и аппаратные маски восстанавливаются из аппаратных разделов по ссылке `hardware-index`. Это уменьшает дублирование данных. В `<editor>` сохраняются нужные редактору флаги, имена, слой и другие сведения.

Объекты с отключённым экспортом не имеют аппаратной записи, поэтому их полное состояние и необходимые ресурсы сохраняются в редакторской части. Ресурсы дедуплицируются; локальный класс `Resources` проверяет ссылки, размер, тип и SHA-256 двоичных данных.

Локальный класс `Fields` объединяет чтение/запись чисел, цветов, флагов и строк, накапливая сообщение об ошибке. Строки с CR требуют специального хранения, поскольку обычный XML нормализует переводы строк.

## Последовательность сохранения

1. `ProjectManager::saveToFile()` проверяет ограничения экспортируемых объектов.
2. `FpgaXmlExporter::compile()` строит аппаратный DOM.
3. `FpgaCompiledDocument::fromDomDocument()` проверяет получившуюся аппаратную часть.
4. `EditorProjectXml::write()` добавляет метаданные.
5. `ProjectXmlFile::write()` записывает документ через `QSaveFile`.
6. Только после успешного `commit()` обновляется путь текущего проекта.

Запись использует Windows-1251. Символы, отсутствующие в кодовой странице, представляются числовыми XML-ссылками. Исходный файл не заменяется частично записанным документом при штатной ошибке сохранения.

## Последовательность открытия

1. `ProjectXmlFile::read()` читает байты, учитывает объявленную кодировку, декодирует и разбирает DOM.
2. `FpgaCompiledDocument` проверяет размеры, схемы, init/data и шрифты.
3. `EditorProjectXml::read()` восстанавливает временный `State` и проверяет ссылки, типы и метаданные.
4. Проверяется согласованность заголовка проекта с рабочей областью `<editor>`.
5. При успехе `ProjectManager` заменяет текущую сцену, очищает историю/буфер и испускает сигналы загрузки.

Ошибка до пятого шага не должна заменять уже открытый проект. В текущем формате для открытия редактором требуется раздел `<editor>`. Произвольный аппаратный XML без него не восстанавливается как полный редакторский проект.

## Где менять формат

- Новый аппаратный параметр: исходная документация модуля → `FpgaSchemaRegistry` → конкретный объект → при необходимости экспорт/компилятор/симулятор → проверки.
- Новый редакторский флаг: `BaseObject` или соответствующая модель → `EditorProjectXml` → клонирование/история → проверка сохранения и повторного открытия.
- Изменение кодировки: `ProjectXmlFile`; не следует добавлять ещё один самостоятельный декодер в окно или панель.
